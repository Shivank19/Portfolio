An end-to-end pipeline that combines classical volatility modeling with hidden Markov regime detection to produce horizon-aware forecasts for S&P 500 and sector ETFs.

−12%RMSE improvement
3Regimes detected
1 / 5 / 21dHorizons

Problem

Standard GARCH forecasts collapse during regime transitions (2008, 2020, 2022). Single-state models can't represent shifting unconditional variance, leading to systematic underestimation of tail risk.

Approach

  1. Fit GJR-GARCH(1,1) per asset and extract standardized residuals.
  2. Train a 3-state Gaussian HMM on residual moments + macro covariates (VIX, yield-curve slope).
  3. Blend per-state volatility forecasts via posterior state probabilities for 1-, 5-, and 21-day horizons.

Outcomes

  • 12% lower RMSE vs. GARCH baseline on out-of-sample 2020–2024 window.
  • Regime labels align with NBER recession dates and CBOE stress windows.
  • Forecasts integrated into a toy risk-parity backtest with improved Sharpe.

Learnings

  • EM initialization matters more than model complexity for HMM stability.
  • Macro features help with regime *identification*, not residual prediction.
  • Writing the evaluation harness first prevented several leakage bugs.

A sparse-attention transformer that predicts residue–residue contact maps for proteins up to 2k residues, designed to run on a single consumer GPU.

0.33×FLOPs vs. dense
2048 aaMax length
−2.3 ppL/5 precision

Problem

Full attention scales quadratically with sequence length, putting long proteins (membrane channels, multi-domain enzymes) out of reach on academic hardware.

Approach

  1. Combine local windowed attention with learned global anchor tokens.
  2. Train on a curated subset of PDB with MSA-derived input features.
  3. Use a custom Triton kernel for the sparse-attention pattern.

Outcomes

  • Within 2.3 pp of dense-attention baseline on long-range contact precision (L/5).
  • Roughly 3× lower FLOPs and 2.4× lower peak memory.
  • Released a small inference CLI used by two collaborating labs.

Learnings

  • Sparse patterns must respect biological priors (secondary structure) to retain accuracy.
  • Profiling kernels with NSight surfaced a 30% latency win I'd otherwise have missed.
  • Reproducible MSAs are a bigger pain than model code.

A discrete-event limit-order-book simulator in Rust with Python bindings, used to evaluate execution strategies under configurable adversarial conditions.

1.2M evt/sThroughput
4 archetypesAgents
Rust + PyLang

Problem

Backtests on historical tape can't model market impact or adversarial responses, so they overstate the performance of large-order execution strategies.

Approach

  1. Event-driven core in Rust with a priority queue and per-price-level FIFO books.
  2. Plug-in agent API: noise traders, momentum chasers, predatory HFT.
  3. PyO3 bindings so research strategies stay in Python notebooks.

Outcomes

  • Sustains ~1.2M events/sec on a single core.
  • Reproduces stylized facts: fat-tailed returns, volatility clustering, hump-shaped spread.
  • Used to show a TWAP variant degrades sharply under adversarial liquidity withdrawal.

Learnings

  • Memory layout (struct-of-arrays for orders) gave a 4× speedup vs. naive design.
  • Determinism flags are essential — non-deterministic sims kill debugging.
  • Rust's borrow checker forced a cleaner event-loop design than my prior C++ attempt.

A reproducible scRNA-seq analysis pipeline that takes raw FASTQs to annotated cell-type atlases with a single command and a config file.

~45 minRuntime / 40k cells
2Labs using it
23Rules

Problem

Small labs were stitching together fragile shell scripts and one-off notebooks, making it hard to re-run analyses or onboard new students.

Approach

  1. Snakemake DAG covering QC, doublet detection, integration (Harmony/scVI), and differential expression.
  2. Dockerized environments per rule, pinned to exact tool versions.
  3. Auto-generated HTML reports with QC plots and parameter provenance.

Outcomes

  • Adopted by two collaborating labs as their default pipeline.
  • End-to-end re-run for a 40k-cell dataset in ~45 minutes on a workstation.
  • Removed an entire class of 'works on my machine' bugs.

Learnings

  • Reproducibility tooling is mostly a UX problem, not a technical one.
  • Defaults that fail loudly beat defaults that silently degrade.
  • Good logs save more debugging hours than fancy dashboards.
